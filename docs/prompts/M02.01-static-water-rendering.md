## Goal
Draw water from each map's `water` layer on top of the land, so I can see how different depths look before any flow exists. The loader already reads the `water` layer; this story is about drawing it.

## Units
Water depth is measured in land-level units: depth 1.0 equals one land level, and the surface is `land + water`. Record this in `docs/design.md` (see Docs below).

## Acceptance
- Water is drawn above the land and **below** the grid lines and the hover highlight, so tile edges stay visible. Confirm that layer order in your plan.
- Use the water base color from `Tileset.water()`. Tiles with no water (depth 0) draw nothing. Alpha rises with depth and is capped so the land under deep water is still faintly visible. Start with alpha rising roughly linearly from 0 at depth 0 to about 0.85 at depth 3, constant beyond that. Put the values in named constants and tell me what you chose. I'll tune them by eye.
- Put the depth-to-alpha mapping in a small pure method and add a unit test (zero at zero depth, never decreasing as depth rises, never above the cap).
- Reuse the existing camera culling; only visible tiles are drawn. The `large` map should hold its FPS.
- New boolean in `ViewSettings`: "Show water", **default on**, with one checkbox row in the settings panel, following the pattern from the earlier settings. Tell me if adding it took more than a field and one row.
- A showcase map, `water-depths`, added with the other maps. It is deliberately physically impossible: a block of flat land with columns or blocks of water at depths 0.1, 0.25, 0.5, 1, 2, 3 and 5. Include the same depths over several different land heights (for example rows over land 1 through 7), so I can see how the blue reads over each land color. Use `meta.name` "Water Depths".
- No sim changes, no flow logic, and no new keys or mappings. Void tiles never have water (the loader already enforces that).
