# Prompt: M1 Land render

(Run after M0.5 is merged. Start in plan mode. Consider `/clear` first so the session starts fresh. Follow the Git workflow in CLAUDE.md: use a `feat/m1-land-render` branch and open a PR when done.)

---

Read `CLAUDE.md`, `docs/design.md` and `docs/roadmap.md`, then do **milestone M1 only**: render land with no water. Show me a plan before editing.

## sim module
1. Map data model: `MapData` (or similar) with `version`, `meta` (name, tileset), `width`, `height`, `int[] land`, `float[] water`. Keep the `Grid` class from M0 and have the loader produce one.
2. `MapLoader`: parse the v1 JSON format from `docs/design.md` using Jackson (pre-approved dependency for `sim` only). Rules:
    - `land` rows are whitespace-delimited ints, values `0..7`. `water` is optional; rows are whitespace-delimited floats, `>= 0`, and must be `0` on void tiles.
    - Row and column counts must match `size`.
    - Unknown keys (including `sources`, `drains`, `obstacles`) are ignored.
    - Errors throw a clear exception naming the problem and the row/column.
3. Unit tests: a valid map, a map with no `water`, unknown keys ignored, wrong row count, wrong column count, land value out of range, negative water, water on a void tile, malformed JSON, unsupported version.

## Test maps
Add hand-written maps (under `core/assets/maps/` or wherever fits the project layout) with names like `flat`, `stairs` (heights 1..7 in a ramp), `bowl`, and `void-island` (void tiles around or inside land). Make at least one map non-square (e.g. 24x12) to catch width/height mixups. One map should be larger (e.g. 128x128), generated by a small script or written out, to exercise culling.

## core module
4. `Tileset` interface: maps a land level to something drawable, plus a water color. Implement `RoygbivTileset` generated in code (solid color squares for levels 1..7 in rainbow order, void = black). No asset files. Select the tileset by the map's `meta.tileset` name through a small registry; unknown names fall back to roygbiv with a logged warning.
5. Map renderer: draws land tiles top-down using the tileset, culling to the visible camera area. No water drawing yet.
6. Camera: pan (mouse drag and WASD/arrows) and zoom (scroll wheel). Zoom limits: min = whole map fits on screen, max = about 64 px per tile. Pan clamps so the map can't be dragged away from the screen entirely (keep the map's edge reachable but don't allow scrolling into empty space beyond it). Handle window resize.
7. Map switching: a key (e.g. `N`/`P`, or number keys) cycles through the maps in the maps folder; also accept an optional command-line argument naming a map to load at startup.
8. HUD: FPS, current map name and size, zoom level, and the tile coordinate under the cursor with its land height.

## Constraints
- Keep game rules out of rendering code and libGDX out of `sim`.
- Camera/clamping math should be testable: put pure calculations (zoom limits, clamp) in a small class that can be unit-tested, and add a couple of tests for it. These may live in `core` tests as long as they don't need a GL context.
- Don't add water logic, sources, drains, or terraforming.

Verify and report: `./gradlew build`, `./gradlew test`, and that the game runs and each test map renders (if you can't open a window here, say so and I'll check visually). List the keys/controls you implemented. Then push the branch and open a PR per the Git workflow in CLAUDE.md.
