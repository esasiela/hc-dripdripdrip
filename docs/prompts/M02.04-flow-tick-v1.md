## Goal
Water flows. The flow algorithm from `docs/design.md` runs in `sim`, tested headlessly with a single scenario: a flat map with one wet tile spreading to its neighbors.

## Scope
- **`sim` only.** No changes to `core` or `lwjgl3`. No rendering, no game loop integration, no settings, no key mappings.
- One test map, defined in code (not a JSON file), to keep the story small. Scenario maps as JSON files are a later story.

## Acceptance

### Flow logic
- A new class in `sim` that owns the flow algorithm, separate from the tick pipeline and the rest of the sim, so the algorithm can be swapped later. It takes a `Grid` (or equivalent) and runs one tick of flow.
- Implements the v1 algorithm from `docs/design.md`:
    1. Double-buffered: read from current water, write into next, swap.
    2. For each non-void tile with water, compute desired outflow to each downhill neighbor (by surface height, not land height): `want = FLOW_RATE * weight * (surface_i - surface_j)`.
    3. Drop any want below `MIN_FLOW` to zero.
    4. Cap total outflow to `MAX_OUTFLOW` (scale proportionally).
    5. No-inversion cap: the source tile's resulting surface must not drop below the highest receiving neighbor's surface. Scale proportionally if needed. This also prevents negative water.
    6. Apply transfers.
- **Neighbor table:** 8 neighbors, orthogonal weight 1.0, diagonal weight ~0.707. Structured so a 4-neighbor option is a config change later, not a code change.
- **Constants** as named values (not magic numbers): `FLOW_RATE = 0.25`, `MAX_OUTFLOW = 1.0`, `MIN_FLOW = 0.001`. Tell me if you see a reason to change any of these during implementation.

### Test map and tests
Define a test scenario in code: a flat map (all land at the same height, bordered by void), all tiles dry except one center tile with a known amount of water. Run one tick and verify:

- **Mass conservation:** total water before == total water after (within float tolerance).
- **Non-negativity:** no tile has negative water after the tick.
- **Void blocking:** void tiles still have zero water.
- **Determinism:** running the same tick twice from the same input produces identical output.
- **Spread verification:** the center tile lost water, its neighbors gained water, tiles beyond the neighbors are still dry. The amounts distributed to orthogonal vs diagonal neighbors respect the weight ratio.
- **No inversion:** the center tile's resulting surface is not lower than any neighbor's resulting surface.
- **Still water:** a separate test — a flat pool at uniform depth across multiple tiles. One tick produces zero change (all differentials are zero).
- **MIN_FLOW threshold:** two adjacent tiles with a surface differential less than `MIN_FLOW` — verify no water moves.
