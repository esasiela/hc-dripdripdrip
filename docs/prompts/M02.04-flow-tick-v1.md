## The algorithm
`docs/design.md` is the spec; follow it exactly. In short, for each non-void tile `src` with water, read only from the current buffer:
1. Find the wanting neighbors: in-bounds, non-void, with `surface_src - surface_nb >= MIN_DIFFERENTIAL`. Sum their differentials as `total_diff`; let `n` be how many there are. No wanting neighbors means skip.
2. `flow = min(total_diff / (n + 1), water[src], MAX_OUTFLOW / TICKS_PER_SECOND)`.
3. Split `flow` among the wanting neighbors in proportion to `weight * diff`. Subtract `flow` from `next[src]` **once** (not per share) and add each share to its neighbor in `next`. Then swap buffers.

Details that matter:
- **Constants:** `TICKS_PER_SECOND = 60`, `MAX_OUTFLOW = 1.0` (water per second), `MIN_DIFFERENTIAL = 0.1` (a depth; never scaled by tick rate). Named constants, not magic numbers, and also settable through the flow class's constructor (defaults = the named constants) so tests can use other values. Tell me if you see a reason to change any default.
- The flow logic is its own class in `sim`, separate from the tick pipeline and the rest of the sim, so the algorithm can be swapped later. It takes the grid/world and runs one tick.
- Never read values written during the same tick. Visit order must not matter.
- Floating point: make sure a tile can never end a tick with negative water because of rounding. Mass conservation is checked within a small tolerance.

## Tests
Use small in-code maps. Where a test needs the speed limit out of the way, pass a large `MAX_OUTFLOW` through the constructor.

- **Mass conservation:** total water before equals total water after one tick and after many ticks (within tolerance).
- **Non-negativity and void blocking:** no tile ever goes negative; void tiles stay at zero and are never sent water.
- **Determinism:** the same input run twice gives identical output.
- **Spread from one wet tile:** flat land bordered by void, one center tile wet. After one tick the center lost water, its four orthogonal neighbors gained equal amounts, and everything farther away is still dry.
- **Symmetry:** the same setup on an odd-sized map, run for many ticks, stays mirror-symmetric left/right and up/down.
- **Two-tile leveling:** a 2x1 map, flat land, one tile wet, speed limit out of the way: after one tick the two surfaces are equal (the sender gave exactly half the differential). Run a few more ticks: nothing changes (no swapping back and forth).
- **Speed limit:** a 2x1 map with a large differential and default constants: each tick moves exactly `MAX_OUTFLOW / TICKS_PER_SECOND` while the limit is the binding term (check a few ticks, and that the total after 30 ticks is about 0.5).
- **Still water:** a flat pool of uniform depth across several tiles: one tick changes nothing.
- **Droplet drains:** a tile on high land holding a small amount of water next to much lower dry land must not cling. With 0.01 (below the per-tick speed limit) it loses all of it in one tick; with 0.05 it is completely gone within a few ticks.
- **Cohesion:** a shallow puddle on flat land with dry flat neighbors, with depth below `MIN_DIFFERENTIAL`: nothing moves.
- **Basin settles:** a small closed basin (flat land bordered by void) with water on one tile and default constants. Run enough ticks for it to settle. Check that water stops moving, that every adjacent pair is within `MIN_DIFFERENTIAL` in surface, and that mass is conserved. If this test does not settle, **do not tune constants or loosen the assertion to make it pass**: report what you saw (tick counts, surfaces) and stop for discussion.
