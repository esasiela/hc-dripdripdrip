# Prompt: M0.5 CI and quality gates

(Run after M0 is merged and `main` is pushed to GitHub. Start in plan mode. Follow the Git workflow in CLAUDE.md: use a `chore/ci-quality-gates` branch and open a PR when done.)

---

Read `CLAUDE.md`, `docs/design.md` and `docs/roadmap.md`, then do **milestone M0.5 only**: CI and code-quality gates. Show me a plan before editing. Use current stable versions of all plugins and actions, and tell me which versions you chose.

Tasks (keep the commits separate, in this order):

1. **Formatting.** Add Spotless with google-java-format to all Java modules and wire `spotlessCheck` into `./gradlew build` (via `check`). Run `spotlessApply` once and commit the result as a **formatting-only commit** with no other changes in it.
2. **Linting.** Add Checkstyle to the Java modules with a modest ruleset that does not conflict with google-java-format (no indentation or line-wrapping rules the formatter already owns). Tell me which rules you enabled. Fix any findings **in the code**. Do not suppress warnings; if you think a suppression is truly warranted, ask me first.
3. **CI.** Add a GitHub Actions workflow at `.github/workflows/ci.yml` that runs on pull requests and on pushes to `main`: check out, set up Temurin Java 21, set up Gradle with caching, and run `./gradlew build`. Name the job `build`. Tests must run headless; if anything needs a display or GL context, tell me instead of working around it.
4. **Local safety hook.** Add a `pre-commit` hook at `scripts/git-hooks/pre-commit` that refuses commits when the current branch is `main` and prints a clear message. Hooks aren't versioned by git, so document the one-time per-clone setup (`git config core.hooksPath scripts/git-hooks`) in `README.md` and tell me the exact command to run. Make sure the script is executable.
5. **Docs.** Update `CLAUDE.md` with the new commands (`./gradlew spotlessApply`, what `build` now checks) and a note to run `spotlessApply` before committing.

Verify and show me: `./gradlew build` passes locally with all checks; deliberately mis-format one file to confirm `spotlessCheck` fails, then revert it. Push the branch, open a PR, and report whether the CI run on the PR passes and the exact name of the CI job/check, because I'll add it as a required status check on `main` afterwards.

Do not change game or sim behavior. Do not add other tools (SpotBugs, Error Prone, etc.); I'll decide on those later.
